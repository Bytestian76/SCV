3. Recomendaciones

  1. Rate-limiting en /api/v1/notificaciones/ — Implementar throttling de 1 req/5s por sesión, o migrar a Server-Sent Events (SSE) para notificaciones en tiempo real.
  2. Reducir intervalo de auto-refresh — Cambiar de 5s a 15-30s en las pantallas de dashboard para minimizar carga.
  3. Token expiry handling — Forzar logout al detectar 403/401 en lugar de reintentar peticiones con token vencido.
  4. Firewall a nivel de aplicación — Las IPs con intentos de explotación conocida (222.212.83.51, 79.124.40.174, 5.61.209.x, etc.) deberían ser bloqueadas temporalmente con fail2ban o similar.
  5. Revisar IP interna 192.168.9.159 — Si no corresponde a un servicio legítimo, investigar origen.
  6. Mantener nginx actualizado — El gateway ya está bloqueando correctamente (código 444) la mayoría de los ataques, pero revisar reglas periódicamente.
  7. Habilitar logs de autenticación — Registrar IP origen en los intentos de login fallidos para detectar patrones de fuerza bruta.
